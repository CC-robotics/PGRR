# 119 “八个场景”要求的口径更正

更正日期：2026-09-16

## 正确理解

教授要求的是 **8 个场景**，不是从已有实验中挑出 8 次 PGRR 成功、Base
失败的单独运行。这里的“场景”至少应满足：

1. 有独立、清楚的交互或失败机制；
2. 场景文件、参数、地图、密度、种子和版本可以固定并复现；
3. Base 与 PGRR 在完全相同的场景条件下配对运行；
4. 不能只看一次偶然结果，需要按预先规定的重复/种子做场景级验证；
5. 场景级结果应稳定显示 PGRR 相对 Base 的优势，同时如实报告碰撞、超时、
   规划失败以及效率代价。

八个场景是否必须对应八种完全不同的机制，仍可向教授确认；但无论如何，
不能用同一场景族中的多次 episode 凑成八个场景。

## 现有两组材料如何重新归类

| 材料 | 数量 | 正确定位 | 计入八场景目标 |
|---|---:|---|---:|
| 新设计并实跑的扩展原型 | 8 类 | 真实场景开发与失败诊断；首轮 PGRR 0/8 到达 | 0 |
| 冻结正式结果中筛出的记录 | 8 条 | 覆盖 5 个族的事后定性 episode 例子 | 0 |
| 后续事件控制候选 | 3 个 | 2 个已实跑负结果，1 个尚未生成可运行 JSON | 0 |

因此，当前教授要求的八个正面场景完成度应报告为 **0/8**。这并不等于此前
工作无效：旧的 600 回合正式结果仍然是有效总体证据；八条记录可用于解释
已有结果；八类扩展原型和事件候选则揭示了恢复过度保守、方向候选不足和
任务完成性差等真实瓶颈。它们只是不能被误报为已经完成了八场景要求。

## 后续口径

- 使用“八条定性例子”称呼冻结 shortlist；
- 使用“八类扩展原型”称呼首轮新场景；
- 只有通过预先固定的场景级配对与重复验证后，才称为“合格场景”；
- 不改动冻结 `moderate_v6` 测试、最终 checkpoint 或正式阈值；
- 下一步先制定场景级晋级规则，再继续筛选，不按单次结果追逐种子。
