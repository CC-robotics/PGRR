# 八类场景恢复循环失败分类

## 本轮完成内容

在上一轮 8 个 PGRR 原始回合、30 个恢复循环的基础上，进一步把每个循环的：

1. 循环开始时的四类失败预测；
2. 学习策略、紧急安全保护和恢复生命周期各自发出的动作；
3. 压缩后的动作序列；
4. 循环结束时相对原始任务目标的距离变化

对应到同一行。30 行循环级明细保存在
`outputs/student/eight_family_pilot/recovery_cycle_classification.csv`。

这里的“正进展”只表示循环结束时比开始时更接近原始目标，严格采用 `> 0 m`，
不是导航成功，也不是预先注册的论文评价指标。

## 主要结果

| 分类问题 | 结果 | 解读 |
|---|---:|---|
| 碰撞风险开始的循环 | 20 | 当前恢复主要由碰撞风险驱动 |
| 其中无正进展 | 18/20（90%） | 碰撞风险触发后的恢复通常没有推进原始任务 |
| 含学习策略决策的循环 | 25 | 大部分循环确实进入了学习策略决策环节 |
| 其中无正进展 | 22/25（88%） | 学习决策出现与无效循环高度共现，但不是因果证明 |
| 学习策略动作事件 | 60 | 按动作与原因变化后的事件计数 |
| WAIT 或 BACKUP | 54/60（90%） | 学习策略几乎都在等待或后退，动作多样性很低 |
| 数值上取得正进展的循环 | 5/30 | 且最大一次仅前进 0.169 m，实际改善很弱 |

数值上取得正进展的 5 个循环全部来自
`recurrent_bidirectional_crossing`。其余 6 个发生过恢复的场景中，每个恢复循环
都没有正进展；第 1 类 `diagonal_cut_in_corridor` 没有触发恢复，因此不进入循环统计。

学习策略在 25 个循环中出现。其中 22 个无正进展循环共记录 55 个学习动作事件：
BACKUP 32 次、WAIT 19 次，另外只有 REPLAN 1 次、临时子目标 3 次。正进展循环中的
学习动作只有 5 次，样本太少，不能据此认定某个动作更好。

## 对当前系统的判断

目前最值得优先检查的不是“模型是否会避碰”，而是以下链条：

`碰撞风险触发 → 可选动作主要剩 WAIT/BACKUP → 短暂 rejoin → 再次触发`

这说明动作掩码、安全覆盖规则和学习策略共同形成了一个保守循环。现有数据不能区分
到底是哪一层承担主要责任，也不能单凭这些结果证明 DAgger 第二轮过拟合。需要在新的
train/validation 开发实验中分别做受控消融。

## 后续开发优先级

1. 先设计不改变现有发布版本的“恢复循环进展检查”接口草案，明确输入、输出和测试；
2. 再为新训练数据增加循环级标签候选，例如是否脱离危险、是否推进原始目标、是否在
   短时间内再次触发；
3. 使用独立 validation 比较旧策略与候选策略，冻结发布模型和最终测试集保持不动；
4. 只有候选 PGRR 能在八类开发场景中取得实际任务完成后，才恢复 Heuristic 和
   Uniform BC 对照运行。

## 结论边界

这是 8 个 train-only 回合的开发诊断，不是统计实验。它能定位下一步工程问题，不能
支持总体优越性、显著性、过拟合或泛化结论。
