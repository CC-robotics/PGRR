# 120 快速寻找 PGRR 优势场景的建议

日期：2026-09-17

## 一、核心判断

最快的方法不是把场景做得越来越难，而是寻找下面这个“可恢复窗口”：

```text
太容易：Base 和 PGRR 都成功
合适：Base 因局部动态冲突失败，但 PGRR 仍有安全方向可以恢复并到达
太难：Base 碰撞，PGRR 把碰撞转化为等待、超时或规划失败
```

我们新造的八类原型大多落在第三档。后续应减少永久阻塞、过窄静态几何和反复循环
行人，优先制造“短时冲突 + 明确释放 + 保留侧向恢复空间”的场景。

## 二、现有数据告诉我们的优先方向

冻结正式结果中，以下 family-density 单元已经出现较强的 Base/PGRR 差异。每个单元
包含五个固定条件：

| 优先级 | 原有机制与难度 | Base 成功/碰撞 | PGRR 成功/碰撞 | 判断 |
|---:|---|---:|---:|---|
| 1 | `crossing_flow / medium` | 0/5，5/5 | 5/5，0/5 | 最强锚点 |
| 2 | `temporary_blockage / low` | 1/5，4/5 | 4/5，0/5 | 强差异且 PGRR 完成性较好 |
| 3 | `head_on_corridor / low` | 3/5，2/5 | 5/5，0/5 | 可恢复对向冲突 |
| 4 | `head_on_corridor / high` | 3/5，2/5 | 5/5，0/5 | 可测试更密集对向交互 |
| 5 | `blind_corner / medium` | 3/5，2/5 | 5/5，0/5 | 遮挡但仍有恢复空间 |
| 6 | `doorway_bottleneck / low` | 3/5，2/5 | 5/5，0/5 | 低密度门口让行 |
| 7 | `crossing_flow / high` | 3/5，2/5 | 5/5，0/5 | 可作为横穿机制的第二几何版本 |
| 8 | `temporary_blockage / high` | 0/5，5/5 | 3/5，0/5 | 差异大，但有 2/5 规划失败，风险较高 |

这八行不能直接当作教授要求的八个场景，因为其中存在同一机制的不同密度，而且结果
来自已冻结测试。但它们可以作为设计新 train/validation 场景的经验先验。若这样使用，
旧测试必须视为已知开发知识，未来论文扩展需要另建新的 held-out test。

## 三、建议优先开发的场景组合

先用五个已有优势机制做母场景，再增加三个机制上真正不同的变体：

1. **中密度单向横穿流**：短时间连续横穿，随后明确形成通行空隙；
2. **盲角单人突然出现**：遮挡造成晚发现，但转角外保留侧向回避空间；
3. **带会车空间的对向行人**：对向冲突后有一侧 passing bay，而不是永久窄道；
4. **低密度门口交汇**：机器人和行人在门口同时接近，但行人有限时通过后离开；
5. **一次性临时封路后释放**：阻挡必须有限持续，释放后原目标路径重新可行；
6. **斜向切入后继续离开**：行人切入机器人前方，但不沿机器人路径永久领行；
7. **开放空间领行人停车并允许侧向超越**：去掉窄墙和 shelf，避免静态碰撞混杂；
8. **错时双行人收口**：两人到达冲突点的时间不同，先形成危险，再形成明确缺口。

第 6—8 项不是已证明合格场景，而是根据现有失败原因设计的优先候选。它们的共同点是：
冲突真实存在，但冲突结束后仍为 21 个临时子目标保留至少一个几何上可行的方向。

## 四、四级快速漏斗

### 第 0 级：离线几何预检，不启动仿真

一次生成约 12—16 个候选，但只检查：

- 去掉动态行人后，机器人到目标的静态路径可行；
- 行人轨迹确实与机器人路线发生时空冲突；
- 冲突结束后行人会释放路线，不会永久循环封锁；
- 冲突区域不是紧贴目标，避免“终点附近双方超时”；
- 临时子目标圆周附近存在开放空间；
- 静态墙体不会成为预期 Base 失败的主要原因。

不满足其中任一条的候选直接淘汰，不花 Arena 时间。

### 第 1 级：单种子 Base/PGRR 配对 smoke

对离线预检通过的候选，各跑一个预先固定的 train seed：

- Base 和 PGRR 使用完全相同的 JSON 与 seed；
- 记录所有 outcome，不重跑覆盖失败；
- 要求事件按设计发生、PGRR 触发恢复、PGRR 最终到达；
- Base 若失败，必须确认失败来自动态交互，而不是静态墙或启动故障。

本级只用于快速淘汰结构不健康的场景，不形成论文结论。

### 第 2 级：三个固定 train 重复

只有第 1 级出现“Base 失败、PGRR 到达”的候选才进入三个预先固定的 train 重复。
建议临时晋级门为：

- PGRR 至少 2/3 到达且 0 碰撞；
- Base 至少 2/3 未到达，其中动态碰撞优先；
- 三次均有完整场景事件和合法 reset；
- 不允许看到结果后更换种子。

该门槛应先让教授确认，不能事后调整。

### 第 3 级：三个独立 validation 重复

通过 train 门的场景冻结 JSON 生成规则和参数范围，再运行三个从未用于修改场景的
validation seed。建议只有 validation 仍满足同一门槛，才称为“候选合格场景”。

八个场景全部确定后，再统一运行 Standard、Heuristic 和 Uniform BC；没有必要在早期
淘汰阶段为每个失败原型运行五种方法。

## 五、节省时间的停止规则

- 一个候选最多允许一次基于机制错误的几何修订；第二次仍出现双方失败就归档；
- 不为寻找理想结果遍历 seed；
- PGRR 未触发：检查事件与触发条件，不增加重复；
- PGRR 触发但没有方向候选：归入算法/掩码研究，不继续加场景难度；
- Base 因静态墙碰撞：场景无效，不能算动态交互优势；
- Base 与 PGRR 都超时：说明超过可恢复窗口，优先降低持续时间或增加释放空间，而不是
  继续增加行人；
- PGRR 单次成功：只能进入重复验证，不能直接计入八个场景。

## 六、我建议的实际执行顺序

1. 首先重建一个新的 `crossing_flow / medium` train-only 锚点，因为旧结果为 Base
   0/5、PGRR 5/5，成功概率最高；
2. 接着做 `temporary_blockage / low` 和带 passing bay 的 `head_on_corridor`；
3. 三者通过单种子 smoke 后立刻做三个固定 train 重复，不同时铺开八类；
4. 若前三类中至少两类通过 train 门，再扩展 blind-corner、doorway 和三个新变体；
5. 若前三类仍全部把 PGRR 变成超时，暂停造场景，转而研究方向候选被清空的问题；
6. validation 通过前，不向论文写入“八个优势场景已经完成”。

这条路线把大量候选生成放在便宜的离线检查阶段，把 Arena 时间集中到最有希望的机制，
同时通过预先固定种子、晋级门和停止规则避免挑选偶然成功。
