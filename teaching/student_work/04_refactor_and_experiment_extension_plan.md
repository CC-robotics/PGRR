# 模块化重构与扩展实验计划（未实施方案）

## 原则

当前 `main` 是已冻结发布的参考实现。任何重构都必须保持公共接口、随机种子、配置路径、ROS 名称和最终证据不变；在离线基线测试未通过前，不修改算法源文件。

## 建议的模块边界

| 边界 | 当前职责 | 重构验收 |
|---|---|---|
| `ramp_core/occupancy.py`、`planning/` | 栅格、A*、短时域规划、专家成本 | 纯函数单测和确定性路径回归通过 |
| `ramp_core/failure/` | 可观测失败规则与状态历史 | 不可引入行人真值；时间窗口边界测试通过 |
| `ramp_core/action_space.py` | 25 个恢复动作与坐标变换 | 动作 ID、顺序、半径和角度不变 |
| `ramp_ml/` | 数据集、网络、损失、训练循环 | HDF5 schema 与 checkpoint 接口保持兼容 |
| `ros_ws/src/` | ROS 消息、节点、bringup | 参数、frame、topic 和 `use_sim_time` 可配置 |
| `scripts/` | 数据、训练、评估、论文管线 | 所有输出目录可配置且不覆盖 final 证据 |

## 今天不实施代码重构的原因

当前机器没有项目要求的 Python 3.10 `ramp-offline`，且 `pytest`、`ruff` 均不可用。没有通过重构前测试基线时改动算法模块，无法证明行为保持不变，也会增加污染冻结发布的风险。

## 首个低风险重构候选

建立离线环境后，优先选择**仅抽取重复的输入验证/指标累积辅助函数**的模块；不改动 A*、失败阈值、动作枚举、模型结构和 YAML 配置。步骤：

1. 在独立分支创建一个最小重构提交。
2. 先运行关联单元测试并记录输出。
3. 抽取纯函数，保持原公开函数签名。
4. 新增一个针对抽取函数的边界测试。
5. 运行 `make test` 与 `make reproduce-small SEED=0`。
6. 只有指标和产物契约一致时，才提交 PR。

## 新场景扩展（设计，不是结果）

| 候选场景 | 要检验的问题 | 固定因素 |
|---|---|---|
| 窄走廊双向会车 | PGRR 是否过度等待或反复后退 | 地图、初始距离、行人速度、seed |
| T 字路口横穿 | 盲区后突然出现动态障碍时的触发质量 | 遮挡长度、出现时刻、密度、seed |
| 电梯口/门口汇聚 | 多人短时聚集造成的死锁 | 门宽、人数、路线、seed |
| 静态障碍加横穿行人 | A* 绕行与动态恢复的协同 | 障碍位置、人流方向、seed |

每个新场景族必须单独按**场景 ID、地图和 seed**划分 train/validation/test，绝不能按帧随机切分。验证集用于选规则和模型；测试集在配置锁定后只评估一次。

## 新实验记录字段

每个 episode 至少保留：`scenario_id`、`map_id`、`seed`、`split`、`method`、`checkpoint_hash`、`config_hash`、终止结果、时间、路径长度、角 jerk、个人空间指标、恢复次数和全部物理尝试记录。

终止结果必须保留：`GOAL_REACHED`、`COLLISION`、`TIMEOUT`、`PLANNER_FAILURE`、`SIMULATOR_FAILURE`、`INVALID_RESET`。不得删除不利 episode；只有后两类基础设施结果可按预先定义规则重试，并保留原尝试。
