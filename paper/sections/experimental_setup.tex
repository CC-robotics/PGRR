\subsection{Platform and Robot}
Experiments use the pinned Arena ROS2 Humble runtime with the Gazebo fallback,
Nav2 NavFn/DWB, and a Jackal model.  The map spans
$31.28\times24.03$ m and the evaluation footprint radius is 0.36 m.  A planar
LiDAR is resampled to the 180 bins consumed by the recovery policy.  The
deployment interface contains only LiDAR, path, velocity, command, progress,
planner-status, and rule-detector histories; simulator poses are isolated for
actor execution, expert labeling, and evaluation.

Pedestrians are LiDAR-visible cylindrical actors following deterministic,
one-shot routes at 5 Hz.  Their swept-step guard holds a candidate motion that
would reduce robot clearance inside the configured 0.90 m soft-yield region;
the 0.73 m hard guard prevents a step from crossing the robot footprint.  This
protocol makes pedestrian motion replayable without treating scripted actor
state as a deployment observation.  It is an interaction stress model rather
than a model of human intent.

\subsection{Moderate-v4 Scenarios and Splits}
The benchmark contains head-on corridor, doorway bottleneck, crossing flow,
blind corner, group blocking, overtaking, opposite streams, and temporary
blockage.  Low, medium, and high densities contain one, two, and four
pedestrians, respectively.  Train, validation, and test use disjoint seed
blocks and compiled scenario hashes.  The held-out test manifest contains five
geometry-offset repetitions for every family--density cell, yielding
\ModeratePairCount{} immutable conditions per method.

All \ModerateMethodCount{} methods run the same condition keys, robot starts,
goals, pedestrian routes, seeds, timeout, and planner profile.  The resulting
publication table therefore contains \ModerateEpisodeCount{} logical
method--episodes before any infrastructure exclusion.  Final generation fails
if a method is missing a condition, if scenario metadata differs across a
pair, or if the observed condition count is not the preregistered value.

\subsection{Baselines and Learned Method}
The closed-loop comparison includes: (i) Base DWB without a recovery subtree;
(ii) the Standard Nav2 recovery behavior; (iii) a rule-triggered Heuristic
policy with the same state machine, planning mask, and safety supervisor as the
learned hierarchy; (iv) Uniform BC using the planning-expert demonstrations;
and (v) PGRR using the validation-selected DAgger checkpoint.  The first four
are complete paired baselines rather than a high-density subset.  The
privileged short-horizon expert is used as a planning reference for labels and
diagnostics only; it is not a deployment baseline, and no optimality claim is
made.

Training and model selection use only train and validation scenarios.  Two
DAgger aggregation rounds are preserved, while the deployed checkpoint is
chosen by validation loss and closed-loop validation behavior.  Margin
weighting remains a reported negative offline ablation.  PPO and a learned
failure detector are outside the evaluated method and are not claimed as
completed contributions.

\subsection{Metrics and Statistical Protocol}
Every stream records physical robot and pedestrian geometry, commands, planner
and recovery state, failure scores, LiDAR, and paths.  We report goal reaching,
collision, timeout, planner failure, SPL, path length, successful-run navigation
time, minimum human-centre distance, personal-space violation, discomfort time,
emergency stops, triggers, recovery success, recovery duration, and
intervention ratio.  \texttt{SIMULATOR\_FAILURE} and
\texttt{INVALID\_RESET} attempts remain in the artifacts and may be excluded
from algorithm rates according to the declared protocol; collision, timeout,
and planner failure are never merged or removed.

PGRR is paired separately with each baseline on identical condition keys.
Binary outcomes use exact McNemar tests and episode-pair bootstrap confidence
intervals.  Continuous paired differences use two-sided Wilcoxon signed-rank
tests, paired bootstrap intervals, and rank-biserial effect sizes.  One global
Holm correction covers all preregistered comparator--endpoint tests.  The
tables report effect sizes and intervals regardless of statistical
significance.

\subsection{Execution and Artifact Integrity}
Concurrent workers use isolated ROS domain IDs and simulator partitions.  A
startup handshake holds actors until navigation, authoritative pose feedback,
and logging are active.  The runner refuses overwrite, records checkpoint and
scenario hashes, retains both attempts after an infrastructure retry, and
requires exactly one accepted terminal result per logical task.  The paper
pipeline first collects the locked run, then validates the complete five-method
condition set, computes statistics, and generates all result tables and figures
from Parquet, CSV, and JSON artifacts.
